# Documentation Rules

## JSDoc Comments
- Add JSDoc comments for every type, interface, and function you create
- Each property of a type/interface must have a JSDoc comment explaining:
  - What it is
  - Its purpose
  - Example of expected values

## Project Documentation
- Always create and maintain docs in a `docs/` folder within each repo
- Use properly structured markdown with clear headings
- Include code examples where helpful

## Code Comments
- Only add comments where the logic isn't self-evident
- Don't add comments that merely restate what the code does
- Use comments to explain "why", not "what"
